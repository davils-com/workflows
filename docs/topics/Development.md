# Developing davils-com/workflows

<link-summary>Repository layout, local checks, tests and releases of this repository.</link-summary>

## Layout

| Path | Contents |
|---|---|
| `.github/workflows/*.yml` | The reusable workflows; `self-*.yml` are this repository's own |
| `actions/<name>/action.yml` | Composite actions; their logic lives in `actions/<name>/scripts/*.sh` |
| `actions/_lib` | `common.sh` and `lib.jq`, shared by the scripts |
| `actions/resolve-config/defaults.yaml` | Every option with its default; the source of the schema and the reference |
| `schemas/davils-ci.schema.json` | Generated by `tools/gen-schema.sh` |
| `examples/` | Caller workflows and configurations for consumers |
| `tests/fixtures/` | Repositories the self-tests run against |
| `tests/scripts/*.bats` | Unit tests of the scripts |
| `tools/` | Lint, generators, `push-tags.sh`, `update-pins.sh` |
| `docs/` | This documentation; `docs/topics/reference` is generated |

## Conventions

- Workflows start with `permissions: {}`; each job takes only what it needs and has a timeout.
- Third-party actions are pinned by commit SHA with a version comment.
- Own actions and workflows are referenced with `$/...`.
- Values reach scripts through environment variables only.
- A new option goes into `defaults.yaml` first; the schema and the reference follow from it.
- Step names are sentences; comments explain why.
- No em dashes.

## Local checks

```bash
tools/lint.sh                 # actionlint, ShellCheck, zizmor
tools/check-pins.sh
tools/check-dashes.sh
tools/gen-schema.sh           # after changing defaults.yaml
tools/gen-flutter-ci.sh       # after changing the inputs of dart-ci.yml
tools/gen-docs.sh             # after changing inputs, outputs or defaults
bats tests/scripts
```

They need bash 4 or newer, yq, jq, actionlint, shellcheck, zizmor, check-jsonschema and bats.

## Self-tests

`self-test.yml` calls the workflows on the fixtures and checks their artifacts: the assembled site,
a compiled binary, a failing fixture that has to fail. Pull requests run a fast selection; the
nightly run adds every operating system and target.

## Releases

Conventional Commits on `develop`, merged into `main`. release-please keeps a release pull request
on `main`; merging it tags `vX.Y.Z` and moves the major tag `v1`. Breaking changes (a removed
input, a changed default with a visible effect, a new configuration version) go into a new major
version.
